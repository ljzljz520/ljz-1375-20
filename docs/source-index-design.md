# 文创来源索引系统 · 设计与验收规格

> 服务对象：文化站
> 目标：为文创商品建立**可追溯、可争议、可复核**的来源索引；管理端负责录入与治理，公开端负责地图、筛选、比较；全系统**不引入交易结算**。

## 0. 设计原则（不可妥协）

| # | 原则 | 含义 |
|---|------|------|
| P1 | **三类地点严格分离** | 设计地 `design_place`、制作地（制造地）`made_at`、销售地 `sold_at` 是三个独立字段/关系，不得互相回填、不得合并展示为单一“产地”。 |
| P2 | **批次是事实的最小载体** | 同名商品的不同批次可能产地不同。制作地、价格生效、证据关系均挂在**批次（Batch）**上，商品级只存跨批次稳定信息。 |
| P3 | **品牌故事不得覆盖制作事实** | 营销文案（brand story）是独立素材，与来源字段分库分权；营销编辑无权写入来源字段，系统不允许用营销叙述派生或覆盖实际制作信息。 |
| P4 | **缺价 ≠ 免费** | 无有效价格记录时，公开页显示“暂无价格”，**禁止渲染为 ¥0 / 免费**。 |
| P5 | **链接探测只判可达性** | 探测结果仅表示 HTTP 访问状态（可达/重定向/失效/超时），**不构成**对店铺真实性、产地真实性的任何证明；UI 不得将“链接可达”表述为“已验证店铺/产地”。 |
| P6 | **证据并列、可争议、可复核** | 冲突证据不自动裁决，并列展示、留痕复核；下架决定沿证据 → 批次 → 商品快照 → 收藏 → 索引单向传播。 |
| P7 | **收藏即封存** | 收藏保存**当时的公开信息快照**；事后素材被撤权时，收藏显示“已失效”，**绝不能重新暴露**已撤回的图片/资料。 |
| P8 | **广告与资料分离** | 页面上广告位与资料内容在 DOM、样式标识、数据来源上清晰区分；发布前同时校验引用来源与媒体可用性。 |
| P9 | **不碰交易结算** | 系统只索引“在哪卖、多少钱（带时间窗）”，不提供下单、支付、订单、分账能力，外链跳转做明确离场提示。 |

## 1. 领域模型

### 1.1 实体总览

```
Product(商品)
 ├─ Batch(批次) 1:N
 │   ├─ made_at ──▶ Place            # 制作地（批次级）
 │   ├─ design_place ──▶ Place       # 设计地（可商品级默认，批次可覆盖）
 │   ├─ Evidence(证据) N:N
 │   ├─ PriceOffer(价格记录) 1:N
 │   ├─ MediaAsset(媒体) N:N
 │   └─ SalesChannelLink(销售渠道链接) N
 ├─ design_place ──▶ Place           # 商品级默认设计地
 ├─ CulturalOrigin(文化出处) N:N
 ├─ BrandStory(品牌故事) 1:N         # 营销域，与来源事实隔离
 └─ ProductSnapshot(商品级快照，比较用)

Dispute(争议) ──▶ Evidence / 字段
TakedownAction(下架/撤权动作)
Favorite(收藏) ──▶ 收藏时点的公开信息快照
SearchIndex(搜索索引，异步最终一致)
AdPlacement(广告位，独立)
```

### 1.2 核心实体（字段级）

**Place（地点）**
`id, type[design|manufacture|sale|culture], name, geo{lat,lng}, region_path[省/市/县], address, source_note`
- 三类业务地点各自独立引用，不建“一个产地走天下”的聚合字段。
- 地图点位按类型分图层着色（设计=蓝 / 制作=赭 / 销售=绿）。

**Product（商品）**
`id, canonical_name, aliases[], category, design_place_id(默认), cultural_origin_ids[], brand_story_ids[], status[draft|published|merged|delisted], merged_into_id, current_snapshot_id, created_by, created_at`
- 商品名稳定，不承载制作事实。
- `merged_into_id` 支持商品合并（见 §6.4）。

**Batch（批次）**
`id, product_id, batch_no, made_at_id(必填), design_place_id(可空,覆盖默认), period{start,end}, materials[](材料), craft_note, status[listed|delisted], version, evidence_ids[], created_at, published_at`
- **关键约束**：`made_at_id` 必须来自带证据支撑的结构化录入，不接受从 brand_story 文本抽取回填。
- 同名商品不同批次可指向不同 `made_at_id`；比较页必须逐批次呈现。

**CulturalOrigin（文化出处）**
`id, name, heritance_level[国家级|省级|县级|未认定], inheritor, source_refs[], region_id`
- “文化出处”是独立维度，与制作地不互相替代（例如：纹样出自 A 地非遗，实际批次在 B 地工坊制作）。

**SalesChannel / SalesChannelLink（销售渠道/链接）**
`channel_id, kind[official_shop|platform_shop|offline|event], display_name, url, sold_at_id(销售地), probe{status,http_code,checked_at,final_url}`
- `probe.status ∈ reachable | redirected | dead | timeout | unknown`，仅访问状态，附检查时间。
- 字段旁固定提示语：*“链接可达性检测不代表店铺或产地真实性”*。

**PriceOffer（价格记录）**
`id, batch_id, channel_id, currency(ISO 4217), price_min, price_max, valid_from, valid_to, observed_at, evidence_ref, status[active|expired|withdrawn]`
- 币种 + 区间 + 渠道 + 生效时间 四要素齐全才有效。
- 同一批次/渠道可有时间重叠外的多条记录；当前价 = 命中 `[valid_from, valid_to]` 且 active 的记录。
- 区间允许 `price_min = price_max`（单值），但 `price_min > price_max` 非法。
- 跨币种**不做静默换算**，需要展示时由前端按标注汇率单独请求并显示换算来源。

**Evidence（证据）**
`id, kind[cert|invoice|contract|report|photo_meta|official_doc|other], uri/attachment_hash, issuer, issued_at, covers{field|relation}, excerpt, confidence, status[active|challenged|invalidated], submitted_by`
- 证据可覆盖：制作地、材料、文化出处、价格、渠道归属等具体字段/关系（细粒度 `covers`）。
- 证据失效只撤它所覆盖的断言，不波及其余字段（最小爆破半径）。

**BrandStory（品牌故事，营销域）**
`id, product_id, copy, author(marketer), approved_at`
- 独立表、独立权限；渲染区块明确标注“品牌自述”，不得出现在来源事实栏。

**Dispute（争议）**
`id, target_type[product|batch|field|evidence], target_id, field_path, claim, counter_claim, evidence_for[], evidence_against[], status[open|in_review|resolved|rejected], resolver, resolution_note, created_at, resolved_at`
- open/in_review 期间，冲突双方**并列展示**，不隐藏任何一方。

**TakedownAction（下架/撤权）**
`id, scope[media|batch|product|evidence], target_id, reason, triggered_by_dispute_id, propagation_log[], created_at`
- 记录完整传播链（见 §5）。

**Version / Snapshot（版本与快照）**
- BatchVersion：批次每次来源字段变更产生的不可变版本（made_at、materials、evidence 集合等）。
- ProductSnapshot：商品级不可变快照（名称、品类、文化出处、汇总状态），供比较与收藏引用。

**Favorite（收藏）**
`id, user_id, target_type[product|batch], target_id, snapshot_payload(JSONB), snapshot_at, state[normal|invalidated], invalidated_reason, retained_public_fields{仅允许保留的白名单}`
- 收藏时把当时**已公开**的字段与媒体引用整体封存。
- 撤权后：媒体引用置 `tombstone`，state=invalidated，展示“该内容已失效”，**不回填、不缓存恢复**。

**MediaAsset（媒体）**
`id, uri, license_status[licensed|revoked|unknown], license_expires_at, alt, credit, usage_refs[]`
- `revoked` 后所有引用点立即收到传播（见 §5）。

**SearchIndex（搜索索引）**
`doc_id, payload, indexed_at, version`
- 异步更新，允许晚到；消费方以 `version/updated_at` 做幂等去重，禁止旧版本覆盖新版本（见 §6.5）。

**AdPlacement（广告）**
`id, slot, creative_uri, link, sponsor_label, active_window`
- 独立数据通道，独立 `<aside data-ad="1">` 容器，与资料区零共享样式类。

### 1.3 关键数据约束

1. `Batch.made_at_id` 上存在触发器/应用校验：发布（publish）时必须至少有一条 `active` 且 `covers=made_at` 的证据，否则禁止发布。
2. 品牌故事保存接口的 DTO 中**物理不包含** made_at/materials/cultural_origin 等字段（白名单绑定），从结构上杜绝营销改来源。
3. PriceOffer 无命中记录 → 读取层返回 `price: null`，前端对 null 只有一种渲染：“暂无价格”。
4. 删除/合并均采用软状态（`status` + 时间戳），保留审计链。

## 2. 角色与权限矩阵

| 能力 | 营销编辑 (marketer) | 来源编辑 (source_editor) | 复核员 (reviewer) | 管理员 (admin) | 匿名访客 |
|------|:--:|:--:|:--:|:--:|:--:|
| 商品名称/品类/别名 | 提建议 | ✅ | — | ✅ | — |
| **材料 / 制作地 / 文化出处 / 批次** | ❌ | ✅（草稿→提交复核） | 复核发布 | ✅ | 只读公开字段 |
| 品牌故事、营销文案 | ✅ | — | — | ✅ | 只读，独立区块 |
| 价格记录（币种/区间/渠道/时间） | ❌ | ✅ | 复核 | ✅ | 只读当前有效价 |
| 证据上传/撤回 | — | ✅ | ✅ | ✅ | 可提交争议 |
| 争议处理 / 下架执行 | — | — | ✅ | ✅ | — |
| 商品合并 | — | 提建议 | ✅ | ✅ | — |
| 广告配置 | 提素材 | — | — | ✅ | — |
| 收藏 | — | — | — | — | ✅（本地/账号皆可） |

要点：
- 来源字段的写路径只有 `source_editor → reviewer → publish`；营销角色对这些端点返回 **403**，且审计日志记录尝试。
- 价格写操作与来源写操作分开授权，避免“改文案顺带改价”。
- 发布动作（publish job）在同一事务里校验：① 每条来源断言都有 active 证据；② 引用媒体 license 可用（见 §7）。

## 3. 管理页（录入与治理）

### 3.1 录入表单结构（分组强隔离）

```
[基础信息] 商品名 / 别名 / 品类 / 默认设计地
[批次信息] 批次号 / 期间 / 材料(可多条,带证据) /
           ◉ 制作地(独立选择器,必选,必挂证据) /
           ◉ 设计地(独立选择器,可继承默认) 
[文化出处] 非遗项目/传承人/认定级别/出处引用   ← 与制作地互不回填
[销售渠道] 渠道类型 / 名称 / ◉ 销售地 / URL /
           链接探测状态(只读,带“不证明真实性”提示)
[价格记录] 币种 / 区间(min,max) / 渠道 / 生效[起,止] / 依据
[证据]   类型 / 颁发方 / 文件哈希 / 覆盖字段(细粒度勾选)
[品牌故事] （独立标签页，营销角色只看得见这里）
```

- 三个地点选择器是**三个独立控件**，各自带地图选点与历史值，不提供“同上”快捷复制。
- 同一商品新增批次时，制作地默认留空，强制重新选填并挂证据，防止沿用上一批产地。
- 价格缺省即留空；表单不存在“免费”勾选项。若确有官方赠送/免费发放，需作为独立 `giveaway` 活动渠道记录，不进入价格体系。

### 3.2 录入校验规则

| 字段 | 规则 |
|------|------|
| 制作地 | 发布前必须有 ≥1 条 active 证据覆盖该字段；证据 challenged 时批次降级为“待复核”，公开页加争议标记 |
| 设计地/销售地 | 可无证据，但 UI 标注“未经证实” |
| 价格 | 币种 ISO 4217；min≤max；时间区间合法；必须绑定渠道 |
| 链接 | 仅保存探测状态与时间；探测失败不阻断录入，但公开端显示“链接失效” |
| 材料 | 自由文本 + 可选证据；多条材料逐条挂证据 |

### 3.3 治理台

- **争议队列**：按目标/字段聚合，左右并列证据卡片（支持/反对），复核员操作：维持、更正（触发新版本）、发下架动作。
- **版本时间线**：批次级版本 diff（制作地、材料、证据集合）与商品级快照并列两个泳道。
- **传播预览**：执行下架前展示影响面（将失效的公开页区块、收藏数、搜索文档）。

## 4. API 设计（REST 摘要）

基础前缀 `/api/v1`，写操作需鉴权，所有变更落审计表。

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/products` | 创建商品（基础信息） |
| POST | `/products/{id}/snapshots` | 生成商品级快照（发布时自动） |
| POST | `/products/{id}/merge` | 合并商品（body: target_id），见 §6.4 |
| POST | `/products/{id}/batches` | 新增批次（制作地必填、证据占位） |
| PATCH | `/batches/{id}` | 修改批次来源字段 → 生成 BatchVersion |
| POST | `/batches/{id}/evidence` | 绑定证据（细粒度 covers） |
| POST | `/batches/{id}/prices` | 新增价格记录（币种/区间/渠道/时间窗） |
| GET | `/batches/{id}/prices?at=ISO8601` | 取某时点有效价；无记录返回 `price: null` |
| POST | `/channels/{id}/probe` | 触发链接探测，回写 `{status,http_code,checked_at}` |
| POST | `/cultural-origins` | 文化出处词目维护 |
| POST | `/products/{id}/brand-stories` | 品牌故事写入（DTO 白名单，仅营销字段） |
| POST | `/disputes` | 提交争议（公开端可提交，需最小证据） |
| POST | `/disputes/{id}/resolve` | 复核裁决（维持/更正/下架） |
| POST | `/takedowns` | 执行下架/撤权，返回 propagation 结果 |
| POST | `/favorites` | 收藏：服务端封存当时公开快照 |
| GET | `/favorites/{id}` | 返回收藏；失效项含 `state:invalidated` 与墓碑 |
| GET | `/public/products` | 公开列表：支持地图/筛选/比较参数 |
| GET | `/public/products/{id}/compare?vs=...&level=snapshot|batch` | 比较 |

**响应约定**
- 价格缺失：`"price": null`（不是 0），公开端渲染“暂无价格”。
- 链接字段：`"probe": {"status":"reachable","http_code":200,"checked_at":"..."}`，同对象恒带 `"authenticity_note": "access_only"`。
- 错误码：来源字段越权写入 → `403 FIELD_FORBIDDEN`，并写明字段名与角色。
- 乐观锁：PATCH 需带 `If-Match: <version>`；版本冲突返回 `409 VERSION_CONFLICT` 并回送当前版本（支撑 §6.2 价格更新冲突）。
- 明确不提供：`/orders`、`/payments`、`/checkout`、分账/发票交易类端点。外链跳转统一经过 `/out?url=...` 离场提示页。

### 4.1 链接探测服务（独立 worker）

- 仅记录：DNS/TCP/TLS/HTTP 状态、最终 URL、状态码、探测时刻。
- 不做：店铺资质判断、产地交叉验证、网页内容真实性评级。
- 探测结果任何 UI 文案不得使用“已认证 / verified / 官方保真”，统一措辞“本次访问可达（时间）”。

## 5. 公开页设计（地图 / 筛选 / 比较）

### 5.1 信息架构

- **资料区**：商品事实卡（来源、批次、证据、文化出处、渠道与价格），视觉主体。
- **广告区**：`<aside data-ad="1">`，固定角标“广告”，独立配色、独立数据请求，禁止混入事实卡数据源。
- **品牌自述区**：独立折叠面板，标题“品牌自述（未经本站核实）”。
- 离场外链：点击销售链接先到 `/out` 提示页（“您将离开本站，本站不参与交易结算”）。

### 5.2 地图

- 三类图层开关：设计地 / 制作地 / 销售地（默认全开，颜色与形状不同，图例常驻）。
- 点选商品后：制作地图钉按**批次**展开多个点（同名商品不同批次不同产地 → 可见多个制作钉）。
- 文化出处作为第四类虚线边界/菱形点呈现，与制作地不重叠含义。
- 聚合不能把不同类型点合并成一颗“一个产地”。

### 5.3 筛选

- 维度：品类、材料、设计地、**制作地（按批次）**、销售地、文化出处/非遗级别、价格区间（按币种分组，不混币种比较）、仅看有争议项。
- 选择“按制作地=X”时，命中逻辑为“存在任一批次 made_at=X”，列表中必须同时展示该商品其他批次的不同产地，避免以偏概全。
- 无有效价的商品可被“暂无价格”筛选项命中，永不进入“免费”桶（系统不存在免费桶）。

### 5.4 比较：商品级快照 vs 批次级版本（两级并行）

比较页提供显式层级切换，两者不可混用：

| | 商品级快照（ProductSnapshot） | 批次级版本（BatchVersion） |
|---|---|---|
| 比较内容 | 名称、品类、文化出处、跨批次汇总、发布时点的公开状态 | 制作地、材料、工艺、该批次证据集、当批渠道与价格 |
| 时间语义 | “某次发布时该商品对外是什么样” | “某批次来源事实第 v 版长什么样” |
| 用途 | 收藏对照、合并前对照、营销页历史 | 产地争议复核、同名不同产地核对 |

- 比较视图对**冲突字段高亮并并列**（例如 A 批次制作地=甲村工坊，B 批次=乙厂），不做“取最新”折叠。
- 证据栏冲突时左右并列 + 争议状态徽标 + “提交争议”入口。

### 5.5 争议呈现与复核闭环

1. 争议 open：争议字段旁显示“存在争议”，详情抽屉内 claim / counter_claim 与双方证据并列，事实不隐藏、不改写。
2. in_review：显示“复核中”，来源字段维持原值但加灰色待核标记；复核期间不允许来源编辑静默改字段（任何修改产生新版本并关联争议单）。
3. resolved-维持：关闭争议，留痕。
4. resolved-更正：字段写入新版本，旧版本仍可查，公开页展示“已于 T 更正”。
5. resolved-下架：触发 TakedownAction，进入传播链。

### 5.6 下架/撤权传播链（单向、幂等、可回放）

```
证据失效(evidence invalidated) / 媒体撤权(media revoked)
        │
        ├─ 覆盖的是字段断言 → 对应批次字段标记 unsupported
        │      ├─ 制作地失去唯一证据 → 批次 delisted（公开页该批次下架）
        │      └─ 商品下所有批次 delisted → 商品 delisted
        ├─ 媒体 revoked → 所有引用点替换墓碑（公开页、快照引用、收藏引用）
        ├─ 已存收藏 → state=invalidated，显示“已失效”，保留白名单文字（名称/失效时间/原因）
        ├─ 搜索索引 → 投递删除/降级任务（异步，幂等，见 §6.5）
        └─ propagation_log 逐节点记录结果，失败重试，支持人工回放
```

规则：
- 传播只“降级/遮蔽”，**不会删除历史版本**（审计可追溯）。
- 撤权媒体即使将来同名文件重新上传，旧引用仍指向墓碑（墓碑键含 asset_id+revoked_at），不能重新暴露。
- 批次下架不株连商品级稳定字段；商品下架后同名合并目标仍可保留谱系指针。

## 6. 关键冲突场景与处理

### 6.1 营销编辑试图修改来源字段（验收点 AC1）

- 前端：营销角色登录后，来源字段控件不渲染（而非只读可绕过）。
- API：角色白名单在服务端强制；请求携带 made_at/materials/cultural_origin 等字段 → `403 FIELD_FORBIDDEN`，记录安全审计。
- 数据层：brand_story 写入走独立 DTO/服务，物理隔离。
- 测试：用营销 token 调批次 PATCH 必须 403，且批次版本号不增长。

### 6.2 价格更新并发冲突（AC2）

- 所有 PriceOffer 写入携带批次/渠道维度的版本号（`If-Match`）。
- A、B 同时编辑：先提交者成功并生成新价格版本；后提交者收到 `409`，前端给出三路合并视图（库内现值 / 我的值 / 共同基线），确认后重放为**新一条带新生效时间的价格记录**，不覆盖历史价。
- 价格记录只追加、不改写；过期靠 `valid_to`，不靠删除。
- 收藏中的价格来自收藏快照，不随后续改价变动（用户看到的是“收藏时价格”）。

### 6.3 图片撤权（AC3）

- 媒体 license 到期/被撤 → 置 `revoked` 并产生 TakedownAction。
- 传播：CDN 引用失效 + 页面换占位墓碑 + 快照中的该图标记不可渲染 + 收藏内同图显示“素材已撤回”。
- 强约束：任何接口（含历史快照、RSS、oEmbed、缩略图接口）对 revoked asset 一律返回墓碑，杜绝缓存/老链接重新暴露。
- 发布作业在发布前预检所有引用媒体 license（见 §7），撤权素材无法进入新发布。

### 6.4 商品合并（AC4）

- 合并只允许在 reviewer/admin 下执行，生成 **MergeReport**：字段差异表（尤其逐批次制作地差异必须显式列出）、证据并集去重、价格记录按渠道时间轴拼接、文化出处并集。
- 被合并商品 `status=merged, merged_into_id=目标`，旧 URL 301 到目标并保留谱系页可查。
- 冲突来源断言不自动取舍：合并后相关批次进入 `in_review`，公开页保留并列标记直到复核结论。
- 收藏：指向被合并商品的收藏给出“已并入 X”，快照仍可查看，不静默改指向。
- 合并可回滚（unmerge 管理动作），因为全程软状态。

### 6.5 搜索索引晚到 / 乱序（AC5）

- 索引消息带 `doc_id, version, indexed_at, op[upsert|delete]`。
- 消费端幂等：存储 max(version)；收到更小版本的 upsert 直接丢弃并打指标；delete 也带版本，防止“先删后到旧 upsert”导致复活。
- 下架/撤权事件的 delete 使用独立高优先队列，但仍遵守版本比较。
- 对账任务定时比对主库与索引（含 delisted 状态与墓碑媒体计数），自动补偿。
- 验收：构造乱序消息序列（upsert v3 → delete v4 → upsert v2 晚到），结果必须等于 v4 删除态。

## 7. 收藏、广告分离与发布作业

### 7.1 收藏：只存当时公开信息

- 收藏动作在服务端从“已发布版本”读取并封存 `snapshot_payload`，包含：商品名、品类、当时公开的批次来源字段、文化出处、**当时有效价格（含币种与时间窗标注）**、媒体引用清单、快照时间、内容版本号。
- 私有/草稿/未发布字段永不入快照。
- 事后变化处理：

| 事后事件 | 收藏表现 |
|----------|----------|
| 价格更新 | 展示“收藏时价格”，另提示“当前价可能已变化（如有）”；当前无价则“当前暂无价格” |
| 批次更正 | 原快照保留可读，旁挂“该信息已更新”链接，指向新版本 |
| 批次下架 | 该批次区块置灰“已下架”，文字仍可读 |
| 图片撤权 | 图片位置显示“素材已撤回”墓碑，**不显示原图、不换用其他图** |
| 商品合并 | 显示“已并入 X”，快照原样保留 |
| 商品删除/全撤 | 收藏卡片整体标“内容已失效”，只保留名称与失效时间 |

- 失效状态由下架传播事件驱动写入，不由前端根据链接探测自行推断。

### 7.2 广告与资料清楚区分

- DOM：广告一律 `<aside data-ad="1" rel="sponsored">`，资料区为 `<article data-source="1">`，自动化测试可断言两者无共同祖先业务容器、无样式类复用。
- 数据：广告走 `/api/v1/ads`，资料走 `/api/v1/public/*`；字段不交叉，广告创意禁止注入来源字段。
- 视觉：广告位固定边框/底色 + “广告”角标；地图图层、筛选器、比较表中不出现广告内容（广告不参与筛选与比较）。
- 外链：广告与渠道链接同样经过 `/out` 离场页；全系统无结算能力声明在页脚常驻。

### 7.3 发布作业（publish job，原子校验）

发布一个商品/批次版本时，在同一事务/同一判定窗口内完成：

1. **引用来源校验**
   - 每个来源断言（制作地必查；材料/文化出处按配置）存在 `active` 证据且 `covers` 精确匹配；
   - 存在 `challenged` 证据覆盖关键字段时，阻断“正常发布”，只能进入“带争议标记发布”（需 reviewer 显式确认）；
   - 品牌故事不参与来源校验，也不能充当证据。
2. **可用媒体校验**
   - 所有被引用图片/附件 `license_status=licensed` 且在有效期内；
   - 撤权/过期/未知许可的素材阻断发布并返回明细；
   - 生成发布快照时记录每个媒体的 asset_id（用于后续撤权精确定位）。
3. **价格一致性**（不阻断但告警）
   - 价格记录四要素完整；缺价允许发布，公开端显示“暂无价格”；系统层面无任何路径把缺价转为 0。
4. **发布产物**
   - ProductSnapshot（商品级）+ BatchVersion（批次级）落库；
   - 投送搜索 upsert（带版本）；
   - CDN/缓存失效；
   - 发布事件写审计（操作人、证据清单、媒体清单、时间）。
5. 发布服务不调用也不依赖任何支付/订单/库存服务。

## 8. 验收用例（逐条可测）

| ID | 场景 | 步骤 | 预期 |
|----|------|------|------|
| AC1 | 营销改来源 | marketer 登录尝试 PATCH 批次制作地/材料/文化出处；尝试经 brand-story 接口夹带字段 | 前端无入口；API 返回 403 FIELD_FORBIDDEN；批次版本不变；审计有记录；品牌故事保存后来源字段无变化 |
| AC2 | 价格并发 | 两账号同批次同渠道同时改价，均基于 v1 | 先成功者生成 v2；后者 409，合并确认后生成 v3（新时间窗），v1/v2 可查；无记录时公开端显示“暂无价格”而非 ¥0/免费 |
| AC2b | 多币种 | 录入 CNY 与 USD 两条价格 | 按币种分别展示，不混算；无汇率标注时不出现换算数 |
| AC3 | 图片撤权 | 对已发布且被 3 处（公开页/快照/收藏）引用的图片执行 revoke | 三处同步显示墓碑；缩略图/oEmbed/历史链接均取不到原图；同名新图不能恢复旧引用 |
| AC4 | 商品合并 | 两个同名商品各有批次且制作地不同，执行合并 | 合并报告逐批次列出制作地差异；冲突批次 in_review 且公开页并列；旧 URL 301；谱系可查；可 unmerge |
| AC5 | 索引晚到乱序 | 投递 upsert v3、delete v4、延迟 upsert v2 | 索引最终为 v4 删除态；对账任务无差异；公开搜索不出现已下架批次 |
| AC6 | 三类地点分离 | 录入设计地 A、制作地 B、销售地 C；同商品第二批制作地 D | 地图四型图层正确；公开页分别标注；筛选制作地=B 命中商品且同时披露 D 批次 |
| AC7 | 链接探测边界 | 渠道 URL 返回 200 但店铺虚构；另一 URL 404 | 200 仅显示“本次访问可达+时间”，不出现任何真实性/官方认证措辞；404 显示链接失效；两种情况都不改变来源事实 |
| AC8 | 争议并列复核 | 对制作地提交相反证据并走完 open→review→更正 | 各阶段 UI 表现符合 §5.5；更正产生新版本，旧版可查，公开页有更正记录 |
| AC9 | 下架传播 | 制作地唯一证据失效 → 批次下架 → 商品全批下架 | 批次/商品依次 delisted；相关收藏变 invalidated 且仅保留白名单文字；搜索收到 delete；传播日志完整可回放 |
| AC10 | 收藏封存 | 收藏后发生改价、撤图、批次下架 | 收藏显示收藏时价格、图片墓碑、下架灰置；无任何已撤素材重新露出 |
| AC11 | 广告隔离 | 页面含广告位与资料区 | DOM/data 属性分离、样式不共用、广告不进筛选/比较/地图；点击经 /out 离场提示；全站无下单支付入口与端点 |
| AC12 | 发布校验 | 引用 1 条过期许可图片、1 个无证据制作地，尝试发布 | 发布被阻断，返回媒体与来源两张问题明细；补齐后成功，快照含证据/媒体清单 |
| AC13 | 缺价渲染 | 商品无任何有效价格记录上线 | 全站所有模板（列表/详情/比较/地图气泡/收藏）显示“暂无价格”，不存在 0/免费字样 |
| AC14 | 品牌故事隔离 | 营销发布品牌故事声称“源自 XX 宫廷造办处”，与批次制作地矛盾 | 品牌自述独立区块+免责声明；制作地字段仍以证据批次为准；比较/地图不引用故事文本 |
| AC15 | 无交易结算 | 走查全部页面与 API | 无订单、购物车、支付、分账、库存接口；外链均离场提示；页脚声明 |

## 10. 落地建议（简要）

- 存储：关系库（实体/版本/审计）+ 对象存储（证据与媒体，哈希寻址）+ 向量/全文索引（异步）；版本字段统一用单调递增 `version` 支持幂等。
- 异步：链接探测、索引更新、下架传播各自独立队列；传播与删除队列分开并可重放。
- 前端：三地点选择器、价格 null 渲染、墓碑媒体组件做成共享基础组件，从组件层防止“免费/产地混用/撤图回显”复发。
- 审计：来源字段每次读写、403 尝试、争议动作、发布校验结果全部留痕，供文化站与复核员追溯。
